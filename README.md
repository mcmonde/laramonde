# multi-app

Laradock-style Docker stack for **multiple Laravel apps** on one host: shared nginx, Postgres, Redis; optional Meilisearch and Mailpit via profiles. Each app gets its own PHP-FPM (or Octane), queue, Reverb, and scheduler.

Same folder-per-service layout as Laradock v18 (`compose.yml` + `defaults.env`), but smaller, current images, and locked down by default.

## Layout

```text
multi-app/
├── docker-compose.yml      # networks, volumes, include list
├── .env.example            # shared settings only
├── dock                    # CLI (optional; docker compose works too)
├── nginx/ postgres/ redis/ meilisearch/ mailpit/ certbot/ workspace/ php-fpm/ php-octane/
├── sites/<app>/            # per-app compose + secrets (generated)
├── apps/<app>/             # Laravel code (or set APP_CODE_PATH_HOST)
└── scripts/
```

Requires **Docker Compose v2.20+** (v2.23+ recommended so `deploy.resources.limits` apply under `docker compose up`; this host uses Compose v5).

No apps are pre-installed. Add each one with `./dock new-app` (see Quick start).

## Quick start

```bash
cd /path/to/multi-app
./dock setup                 # strong secrets + host detect + Scout/Mail sync
./dock up                    # shared nginx, postgres, redis (+ profiled services)

./dock new-app portal portal.local
# Clone into apps/portal (dir has .gitkeep — use rsync or remove it first):
#   git clone your-repo /tmp/portal && rsync -a /tmp/portal/ apps/portal/ && rm -rf /tmp/portal
# merge sites/portal/.env.laravel.example into apps/portal/.env

echo "127.0.0.1 portal.local" | sudo tee -a /etc/hosts
./dock up
./dock artisan portal key:generate
./dock artisan portal migrate
```

Open http://portal.local (bound to `127.0.0.1` by default). With `dev` profile: Mailpit UI http://127.0.0.1:8025

```bash
./dock workspace          # php, composer, node, git (profile: dev)
./dock logs nginx
./dock backup
./dock validate           # compose config + bash -n
```

## Secrets

`./dock setup` generates **96-char hex** passwords for Postgres/Redis and a **64-char hex** Meilisearch master key. Placeholders like `change-me` are rejected.

```bash
./dock setup                      # create .env, fill weak secrets only
./dock setup --rotate-secrets     # force-regenerate stack secrets
```

Per-app DB passwords and Reverb keys are generated by `./dock new-app` (64-char hex DB password).

## Profiles

`.env.example` defaults to `COMPOSE_PROFILES=dev,search` (workspace + mailpit + meilisearch).

| Profile | Services |
|---------|----------|
| `dev` | workspace, mailpit |
| `search` | meilisearch |
| `mail` | mailpit only |
| `tls` | certbot renew loop |
| `build` | php image builders |

`./dock setup` and `./dock resources apply` sync app env from profiles:

| Profiles | Scout | Mail |
|----------|-------|------|
| `search` on | `SCOUT_DRIVER=meilisearch`, host `http://meilisearch:7700` | — |
| `search` off | `SCOUT_DRIVER=null`, empty host | — |
| `dev` or `mail` | — | `MAIL_MAILER=smtp`, `MAIL_HOST=mailpit` |
| neither | — | `MAIL_MAILER=log` (no mailpit required) |

Lean production:

```env
COMPOSE_PROFILES=
NGINX_BIND=0.0.0.0
MEILI_ENV=production
```

Then `./dock setup` (or `resources apply`) sets Scout→null and Mail→log. Start search later by adding `search` to profiles and re-running setup/apply.

```bash
./dock up   # nginx postgres redis + apps; meili/mailpit/workspace only if profiled
```

## SPA + API on one domain (`--spa`)

Your usual layout (no subdomains; Reverb keeps `/app`):

```text
nameofsite.com/       → SPA  (apps/<name>/frontend/dist)
nameofsite.com/api/   → Laravel
nameofsite.com/app    → Reverb / Echo only
```

Full local playbook is in the Quick start / SPA sections below — no sample apps ship in this repo.

```bash
./dock new-app portal portal.local --spa
# or with Octane:
./dock new-app portal portal.example.com --octane --spa
```

Then:

```bash
# Laravel — apps/<name> already has .gitkeep, so clone via rsync:
git clone git@github.com:org/portal-api.git /tmp/portal-api
rsync -a --delete --exclude frontend/ /tmp/portal-api/ apps/portal/
rm -rf /tmp/portal-api

# SPA repo — build writes to frontend/dist/
git clone git@github.com:org/portal-spa.git apps/portal/frontend
cd apps/portal/frontend && npm ci && npm run build
# ensure Vite/base is "/" (site root), API calls go to /api

# Merge sites/portal/.env.laravel.example (APP_URL=…/api, FRONTEND_URL=site root)
echo "127.0.0.1 portal.local" | sudo tee -a /etc/hosts
./dock up --force-recreate
```

nginx also sends these to Laravel (not the SPA): `/sanctum/*`, `/broadcasting/*`, `/up`.

Convert an existing app:

```bash
# sites/<app>/defaults.env
APP_LAYOUT=spa
APP_URL=http://nameofsite.local/api
./dock site:render <app>
./dock restart nginx
git clone <spa-repo> apps/<app>/frontend && cd apps/<app>/frontend && npm ci && npm run build
```

SPA `try_files` falls back to `index.html` for client-side routers. Frontend `base` must be `/` (not `/app/dist`).


## Host resources (auto-detect)

Always starts from **this server's real CPU/RAM**.

```bash
./dock setup
./dock resources             # assess
./dock resources apply
./dock resources status
./dock resources weight portal 2
./dock resources pin portal
```

`rooms left` subtracts existing apps by **effective weight** (Octane ×1.25), not raw count.

| Level | When | Behavior |
|-------|------|----------|
| OK | &lt; 75% budget | continue |
| WARNING | ≥ 75% | prompt `[y/N]` |
| CRITICAL | ≥ 95% | prompt |
| BLOCKED | over hard mins | abort (unless `--force` or `RESOURCE_MODE=unlimited`) |

### No Docker limits (`RESOURCE_MODE=unlimited`)

Use when you want containers to share the host freely (e.g. tiny 2GB droplet). Compose treats `cpus`/`memory` `0` as **no cgroup caps**. Capacity hard-blocks become warnings only.

```env
# .env
RESOURCE_MODE=unlimited
```

```bash
./dock resources apply
./dock up --force-recreate
```

Switch back with `RESOURCE_MODE=auto` then `./dock resources apply`.  
`./dock profile small|medium|large` resets to `auto`.

Warning: under memory pressure the **kernel OOM killer** may stop Postgres/Redis/nginx unpredictably — prefer more RAM when you can.

## Adding / removing apps

```bash
./dock new-app portal portal.example.com
./dock new-app billing bill.local --octane
./dock db:create portal          # if Postgres was already initialized

./dock remove-app portal         # stack only; keeps DB + apps/portal
./dock remove-app portal --drop-db --remove-code --force
```

## Isolation

| Resource | Shared? | Isolation |
|----------|---------|-----------|
| nginx | Yes | Host-based routing |
| Postgres | Yes | Database + role per app (TLS off inside Docker network; terminate TLS at nginx) |
| Redis | Yes | `REDIS_PREFIX` + password |
| Meilisearch | Optional (`search`) | `SCOUT_PREFIX` + master key |
| PHP / Reverb / storage | Per app | Separate containers / bind mounts |

## Security (vs stock Laradock)

- Strong hex secrets from `./dock setup`; compose refuses empty Postgres/Redis passwords
- Ports bind to **127.0.0.1** by default
- Postgres / Redis / Meilisearch not published to the host
- Split frontend / backend networks; Redis AUTH; FLUSH* renamed away
- Unprivileged nginx; `cap_drop: ALL`; `no-new-privileges`
- `.env` and `sites/*/defaults.env` mode `600`, gitignored

## TLS (Let's Encrypt)

```bash
# .env: NGINX_BIND=0.0.0.0, CERTBOT_EMAIL=you@example.com, CERTBOT_STAGING=0
./dock tls:issue portal
./dock tls:status
./dock tls:renew
./dock tls:disable portal
```

Cron:

```bash
0 3 * * * cd /path/to/multi-app && ./dock tls:renew >> logs/tls-renew.log 2>&1
0 4 * * * cd /path/to/multi-app && ./dock backup >> logs/backup.log 2>&1
```

## Production notes

- Prefer empty `COMPOSE_PROFILES` unless you need Meili/workspace/mailpit
- Do not `FLUSHALL` on shared Redis (renamed away)
- Back up Postgres (`./dock backup`) and Meilisearch volume if `search` is on
- After `--rotate-secrets`, recreate volumes or update credentials in-place if services already started with old passwords
